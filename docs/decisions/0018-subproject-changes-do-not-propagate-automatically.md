# ADR 0018：子 Project 的变化不自动传播到父电路

## 状态

已确认

## 背景

[ADR 0014](0014-subcircuit-by-reference-flattened-simulation.md) 决定 Subcircuit 按引用组合：父 Project 记录子 Project 的相对路径，打开父 Project 时读取子 Project 并展平为普通元件，子 Project 文件在父 Project 打开期间的变化不自动生效，由用户执行"重新加载子电路"命令。当时否决自动重载的理由是"会在用户编辑中途改变端口列表并使 Connection 悬空，用户无法预期"。

多文档与下钻引入了一个 ADR 0014 没有覆盖的情形：变化不再来自外部编辑器，而是来自本应用内的另一个标签页，由用户自己保存。这时"无法预期"这条理由明显弱化——用户当然预期自己刚保存的东西会生效。但**后果一点没变**：端口列表一旦改变，父电路中相关的 Connection 立刻悬空。

需要决定的是：这种来自本应用内部的子 Project 变化，以什么方式、在什么时刻影响父电路。

## 决策

### 未保存的改动不穿透

父电路使用的始终是**磁盘版本**的展平副本。子文档标签页中未保存的编辑只影响该标签页自己的仿真，不改变父电路中该 Subcircuit 的展平副本。

直接后果是同一个子 Project 在两处可能显示不同的信号值：子文档标签页显示编辑后的版本，父电路仍跑旧版本。这是必须承认的代价，用标签页上的未保存标记让它可见。

### 保存后不自动重载，但产生可见提示

用户在子 Project 中保存后，父文档出现"子电路已变化，需重新加载"的提示状态。重新加载仍由用户执行 ADR 0014 已有的"重新加载子电路"命令，作为一个可撤销的历史帧。

重载后的端口匹配沿用 ADR 0014：按名字匹配，能对上的 Connection 保留，对不上的成为 [DanglingConnection](../../CONTEXT.md)。

### 本应用内部的保存不改变触发点

"重新加载子电路"仍然是父电路重解析的**唯一**触发点。本决策只增加一个提示状态，不增加任何自动触发路径。

## 未采用的方案

### 保存即自动重载

不采用。ADR 0014 否决自动重载的理由（用户无法预期）在变化来自本应用时确实弱化了，但自动重载并没有因此变好：端口列表一变 Connection 就悬空这个后果完全不变，自动重载只是把悬空推迟到用户没在看父文档的时刻发生——用户正在子电路里专注工作时，父电路被静默改坏，而且没有对应的历史帧可撤销。

### 未保存的改动穿透到父电路

不采用。它要求父电路的展平副本实时跟随子文档的内存状态，等价于真正的自动重载，并且让**保存**这个动作在层次结构里失去意义：同一个子电路会同时有"内存版"和"磁盘版"两个消费者，而"父电路看到的到底是哪一版"变成一个无法从界面判断的问题。

### 在父文档打开期间监听子 Project 文件

沿用 ADR 0014 的否决，理由不变——文件系统层面的监听同样是用户无法预期的变化来源。

## 后果

- 界面需要同时表达三个独立状态：**未保存**（子文档有改动未落盘）、**未重载**（子文档已保存，父电路的展平副本是旧的）、**未解析**（子 Project 文件缺失或校验失败）。前两者不能合并成一个"脏"标记——它们的主体不同，一个是子文档、一个是父文档。
- 检查器在显示 Subcircuit 的引用路径与解析状态之外，还需要显示"父电路持有的是哪个版本"。
- 本决策细化 ADR 0014，不推翻其任何结论。"重新加载子电路"的语义、端口按名字匹配、悬空连接的处置都保持不变。
