# ADR 0013：Wire 外观与信号状态分离

## 状态

已确认

## 背景

Wire 目前用颜色、线宽、虚线和光晕共同表达 `0 / 1 / X`。当用户需要用颜色整理电路时，线路颜色会与仿真状态冲突；未知信号的虚线又会与选择、焦点和悬空状态叠加，难以判断当前视觉反馈的来源。

## 决策

Wire 的线路外观与数字信号状态分离：

- 每条 Wire 保存一个受限的颜色预设 ID，线路在 `0 / 1 / X` 之间变化时不改变颜色、线宽或线型；
- 完整连接的信号值用等宽文字 `0 / 1 / X` 表达，文字常显于 Route 中点；流向由叠加在 Route 上的 CSS 虚线动画表达，虚线沿 source 输出端流向 target 输入端；
- 悬空 Wire 不显示信号流文字，仅由悬空端点控件表达待修复状态；
- 选中与键盘焦点使用连续外层描边，内层保留 Wire 自身颜色；
- 用户可以从 Wire 对象菜单修改单条线路颜色，修改属于本地编辑器历史，不调用仿真引擎；
- 元件库侧栏提供新建 Wire 的默认颜色。该偏好保存在本机，既有 Wire 不随默认值变化；
- 颜色只接受内置预设 ID，文档或本地存储中的缺省、未知值回退到“电气蓝”，不接受任意 CSS 值。

大场景关闭流动虚线，只保留静态信号文字；系统启用“减少动态效果”时采用同一降级。降级只停止运动，不移除 `0 / 1 / X` 文本。

## 未采用的方案

### 继续用交通灯颜色表达信号

不采用。它占用了用户整理线路所需的颜色维度，并让颜色同时承担结构分类和仿真状态两个职责。

### 允许任意颜色选择器

不采用。任意颜色难以保证深色、浅色主题中的对比度，也会扩大项目文件兼容和可访问性验证范围。

### 用粒子或光点表达信号流

不采用。粒子仍需额外图例才能区分 `0 / 1 / X`，而文字可以直接、非颜色地表达信号值。

## 后果

- `EditorConnection` 增加可选颜色预设，旧文档无需迁移即可使用默认色；
- `CanvasWire.signal` 继续由仿真快照更新，但只驱动信号文字内容，不再驱动线路样式；
- 单条 Wire 改色需要支持撤销和重做，同时保持 C++ Circuit 不变；
- SVG Route 必须保持 `output → input` 的路径方向，虚线流动方向才能与电气方向一致；
- 截图回归需要覆盖正常、选中、悬空、减少动态效果与高密度场景。

## 修订（2026-09-18）

信号流的实现从「沿 Route 移动的 SMIL 文字」改为「静态信号文字 + CSS 流动虚线」。

原实现给每条 Wire 渲染三段沿 `textPath` 移动的信号文字，靠 SMIL 动画 `startOffset` 驱动。`startOffset` 是排版属性：目标规模（500 Component / 1,000 Wire）下每帧都会让 1,000 段文本沿路径重新排版，并持续弄脏布局树，使任何一次强制样式或布局重算都要为此付出代价。实测这一层单独贡献约 66ms 的帧间隔，是 Phase 3 性能验收未达标的两个根因之一。

取代它的 CSS `stroke-dashoffset` 动画只触发重绘、不触发文本排版，并让信号文字从三份移动副本收敛为一份常显文字，每条 Wire 的 DOM 元素从 10 个降到 5 个。选择虚线而非「未采用的方案」中否决过的粒子或光点，是因为虚线只是流向指示，不承担信号值表达——`0 / 1 / X` 仍由等宽文字直接表达，那条否决理由依然成立。

代价是流动元素不再携带信号值：正常模式下信号值出现在 Route 中点，位置固定，不再随流动移动。截图回归与 `canvas exposes non-color state hooks for ports and wires` 中的视觉契约断言已同步更新。
