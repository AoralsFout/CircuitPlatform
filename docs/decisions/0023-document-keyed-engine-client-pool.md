# ADR 0023：按文档键隔离 Electron 引擎客户端

## 状态

已接受

## 背景

C++ 引擎协议是一条 JSON Lines 长连接，一个进程只承载一份 `Circuit` 和一份
`Simulation`。多文档工作区不能让多个文档共用这条连接，否则 requestId、行缓冲、
进程故障和引擎内部 ID 会跨文档混用。

## 决策

Electron 主进程使用 `EngineClientPool` 按文档键懒创建 `EngineClient`。文档键只存在于
Electron IPC 边界；发给 C++ 的 JSON 请求类型和字段保持不变。

- 同一个文档键复用一个客户端，第一次业务请求才启动它的进程。
- 每个客户端独立维护请求匹配、行缓冲、死亡原因和进程代号。
- 健康检查与重启按文档键执行；没有文档时使用一次性探针，不把探针注册为业务文档。
- 关闭文档只回收对应客户端并拒绝其待处理请求；应用退出回收全部客户端。
- `preload` 继续提供默认文档桥接，并提供 `forDocument(key)` 给多文档协调器使用。

## 后果

协议和 C++ 引擎无需感知文档维度；一个进程异常退出只影响对应文档。进程数随打开文档数
增长，暂不设置额外上限；后续若引入资源限制，需要另行记录生命周期与淘汰策略。
