# ADR 0015：位宽是 Port 的属性，信号值是逐位三值

## 状态

已确认

## 背景

用户希望单个 Port 和 Connection 能承载多位信号，减少 ALU 这类 Subcircuit 的端口数量——现在两条 8 位操作数加一条 8 位结果就是 18 个端口。

现状约束：

- `SignalValue` 是三值标量枚举 `{Zero, One, Unknown}`，到处按值传递、按 `==` 比较；
- `Port` 恰好是 `{name, direction}`，没有位宽；`PortId` 是 `(ComponentId, 字符串名字)`，端口身份靠名字而非下标；
- `invert`、`andValue`、`orValue`、`xorValue` 是三值逻辑的标量原语；
- 引擎里没有任何多位概念的现存实现，领域文档里也没有对应术语。

## 决策

### 位宽是 Port 的属性

- `Port` 增加位宽，成为 `{name, direction, width}`。位宽为 1 时与现在完全等价；
- 不引入 `Bus` 领域对象。总线是「位宽大于 1 的 Port 或 Connection」的口语说法，不是独立概念；
- `Connection` 因此不需要新字段，它传递的就是两端 Port 声明的那个位宽。

### 值是逐位三值

- `SignalValue` 从三值标量变为多位值：一个 N 位值是 N 个独立的 `0 / 1 / X`；
- 已有的四个标量原语签名不变，只是体内按位循环，逐位化是直接映射；
- 某一位未知不影响其余位，用户看到的是 `XXXXXX1X` 而不是整条 `XXXXXXXX`。

### 位宽不改变线路外观

- 线路颜色仍只由用户在 `EditorConnection` 上通过预设选择，这条延续 ADR 0013；线宽与线型目前固定，不随信号值变化，放开它们需要单独的决策；
- 位宽是结构而非信号，让总线画得更粗在原则上不违反 ADR 0013，但它会挤占画布的视觉预算，位宽大时线会粗到遮住画布；
- 位宽改由端口标签的位区间（`名字[7:0]`）和二进制信号文本（总线显示 `1010`，标量显示 `0`）表达。

## 未采用的方案

### 总线是若干具名 1 位网络的集合（Logisim 式）

不采用。「某束的第 k 位」会成为端口身份的一部分，而端口身份是 `(ComponentId, 字符串名字)`，`samePort` 和 `findPort` 在 `circuit.cpp` 与 `simulation.cpp` 各有一份重复实现，ADR 0003 的悬空与重接规则要按位重写。它唯一比位宽模型强的地方是能对某一位单独布线，而这个能力在位宽模型上用一个拆线元件就能补出来；反过来做不到。

### 位宽编码进端口名（`out[7:0]`）

不采用。编辑器的 `EditorBindings` 和 `CircuitEnginePort` 把端口当不透明字符串透传，所以这条路在编辑器层几乎零成本，很有诱惑力。但它把类型信息塞进字符串，将来校验位宽就要解析名字；而 ADR 0014 已经预言端口列表会从常量变为可按数据计算，结构化字段是那句预言的直接落点。

### 值用整体三值（整个值要么确定，要么整体未知）

不采用。整体未知时 8 位结果里只错一位就整条显示未知，用户无从定位；而且「什么时候整体塌成未知」需要额外发明聚合规则，逐位化则不需要任何新规则。将来加法器的进位传播也只能靠逐位未知表达「低位已知、高位未知」。

## 后果

- 协议中的信号值统一为字符串（`"0"`、`"1"`、`"X"`、`"1010"`、`"X1X0"`），长度必须等于端口位宽。这清掉了现在「`0`/`1` 是数字、`X` 是字符串」的混用，是一次破坏性改动；选择现在做，是因为 Phase 5 尚未开始，磁盘上没有任何需要兼容的项目文件；
- `Simulation::signals_` 的每一项从标量变为一个多位值，`settle` 的定点迭代终止条件仍是逐元素比较，语义不变；
- 位宽上限不作为领域约束。真要优化性能时再引入打包表示，不会推翻本决策；超宽 Port 在画布与波形上的显示降级另议；
- 位宽在创建后的修改需要新的协议请求，`component_added` 也要回传实际端口清单，前端才能不再持有第二份端口定义；两者见[项目路线图](../roadmap.md) 的 Phase 4.5；
- 波形和项目文件在 Phase 5 一次按多位值设计，不需要为标量快照保留兼容路径；
- 落地记录：本决策由 [ADR 0020](0020-port-list-is-the-only-authority.md) 在 Phase 4.5 落地——位宽成为 `Port` 的固有属性，`SignalValue` 变为逐位多位值，协议中的信号值统一为字符串；上面「位宽在创建后的修改需要新的协议请求」也已落地为 `set_port_width`，`component_added` 与 `port_width_set` 回传该 Component 实际的端口清单，前端不再持有第二份端口定义。
