# ADR 0027：父工程保存子电路导入快照

## 状态

已接受（已实现）

## 背景

[ADR 0014](0014-subcircuit-by-reference-flattened-simulation.md) 让父 Project 按路径引用子 Project；重新打开父 Project 时会再次读取子文件。这样父工程的行为受源文件内容和位置影响。用户希望一次导入后父工程独立保存当时的电路及完整嵌套结构，源文件变化仅通过显式重新导入生效。

实施规格见 [Issue #67](https://github.com/AoralsFout/CircuitPlatform/issues/67)。

## 已确定的取舍

- 父 Project 保存导入的 Subcircuit 定义及其递归依赖，而不是只保存源文件路径和端口缓存。新文件格式不兼容旧版 Project；不做旧文件自动迁移。
- 一次导入得到一组自包含的定义。画布上多次放置同一导入定义时，共享其结构，但每处拥有独立的仿真状态。导入 A 遇到此前已导入的 B 时，A 保存自己当时所需的 B 快照，不更新或借用旧版 B。
- 导入定义在父 Project 内只读。源文件内容或位置变化不改变已导入的定义；更新必须显式重新导入。
- 左侧新增独立的“子电路”页，以导入定义及其嵌套依赖为树的主体。没有画布放置位置的定义仍保留，直到用户明确删除。
- 树节点和画布上的子电路元件可以打开父 Project 所拥有的只读电路标签，不依赖源文件仍存在。文件选择导入维持“导入并放置”入口，树页另提供“仅导入”和“再次放置”。
- 每次执行“从文件导入”都会创建新的定义快照；从树中“再次放置”才复用已有定义。导入和重新导入只读取源 Project 已保存的内容，不读取其他标签页中未保存的改动。
- 父 Project 不保存用于解析或重新导入的源文件路径。重新导入时由用户重新选择文件；所选文件的位置不改变既有定义的身份。
- 用户可以选中任意嵌套定义重新导入：该定义及其递归依赖作为一次更新提交，其所有放置位置采用新内容。选中上层定义则更新整棵下层结构。
- 删除仍被使用的定义需要先说明受影响的使用位置，再经用户再次确认。确认后删除定义，但保留使用它的 Component 及其 Connection，并将使用处标记为定义缺失。
- 重新导入后的 Port 只有名称、方向和位宽全部匹配时才保留原 Connection；其余 Connection 成为 DanglingConnection，不自动猜测新端口。
- 重新导入必须先完整读取和校验所选定义及其递归依赖。读取、校验或循环检查失败时保留旧快照和仿真结构，只显示错误。
- 重新导入和确认删除各构成父 Project 中一帧可撤销的历史；撤销需要同步恢复定义、树结构、端口映射和使用处状态。
- 重新导入保留所选定义在父 Project 内的身份与显示名称，即使用户选择了另一个文件；修改名称是单独的操作。
- 快照保存源 Project 已落盘的 Circuit、编辑器布局、标签、输入值、Port 顺序，以及该 Circuit 实际使用到的递归定义；源 Project 中未被使用的闲置定义不随导入复制。不保存源文档的 SimulationState、波形、撤销历史或视口位置。
- 若局部重新导入嵌套定义会使只读的上层定义出现 DanglingConnection，则拒绝该次更新并保留旧定义；用户需要重新导入相应上层定义。顶层 Circuit 可编辑，因此其 Port 不兼容时沿用悬空连接规则。
- 重新导入及撤销后的受影响展平子树从初始仿真状态重新开始，未受影响部分保持状态；结构撤销不回拨整个仿真时间。
- 打开的只读标签跟随定义身份：重新导入时显示新内容；定义删除时显示“定义已删除”，撤销删除后恢复。
- 强制删除后的定义缺失 Component、端口缓存和 Connection 可以保存并重新打开；仿真跳过缺失子树及穿过它的 Connection，其他分支继续运行。
- 定义缺失的使用处可以改指向现有导入定义，也可以从文件导入新定义修复；顶层 Port 不匹配时保留 DanglingConnection，只读嵌套定义内则拒绝不兼容替换。
- 整树重新导入只保留所选根定义的身份，下层旧定义随旧树移除，新树获得新身份。旧下层只读标签进入“定义已删除”状态；撤销可以恢复旧身份与标签内容。
- 重复导入允许同名来源形成多个独立定义；左侧显示名称自动加序号区分，并允许用户另行改名。
- 画布上的 Subcircuit 标题仅在显示时省略文件扩展名 `.circuit.json`，同名序号如 `(2)` 仍显示；所有非画布位置（包括左侧视图、只读标签和检查器）继续显示完整名称。定义保存的显示名称不因画布格式化而改变。
- 重新导入若会使可编辑的顶层 Circuit 产生 DanglingConnection，先列出受影响的 Port 和 Connection，确认后才提交；没有断线时不增加确认步骤。
- 可导入已保存但包含定义缺失或 DanglingConnection 的新格式 Project，明确展示警告并保留可运行部分；格式损坏或定义成环则拒绝导入。旧格式 Project 既不能作为父工程打开，也不能作为导入来源。
- 只读的内嵌电路标签仅展示定义结构，不产生独立 SimulationState，也不显示某个放置位置的实时信号。实例内部的实时值继续从父画布选中的 Component 在检查器中查看。
- 内嵌定义及其实际使用到的递归定义可导出为独立、可编辑的新 Project；导出不修改父 Project，后续修改只有显式重新导入才进入父 Project。
- 子电路进入引擎前仍展平；本决策不要求引擎持有层次结构。ADR 0014 关于按路径引用和下钻打开源 Project 的语义需要由本决策替代，展平与各放置位置的独立仿真状态继续沿用。

## 结果

项目文件不再依靠源文件的存在、内容或位置恢复层次电路；普通打开、另存为和引擎恢复均只消费父 Project 保存的定义。没有源路径也意味着不再自动提示“源工程已变化”；用户自行选择何时重新导入。

本 ADR 取代 ADR 0014 中按路径引用、重新打开时递归读取源文件及下钻打开源 Project 的决定。ADR 0014 的接口形成规则与展平仿真继续有效。ADR 0018 和 ADR 0025 中基于源路径的 stale 提示不再适用。
