# ADR 0012：输入设置按编辑器元件绑定驱动

## 状态

已确认

## 背景

输入设置最初只服务于固定 AND 示例，因此工作区只保存 `inputA` 和 `inputB`，编辑器侧也只取前两个 Input Component。用户在画布中添加第三个输入后，它既不会出现在输入设置中，也不会被提交给仿真引擎。

## 决策

工作区使用由编辑器 ID 索引的输入绑定集合。重新绑定仿真时收集所有类型为 `input` 的 Component，并在每次求值前按绑定顺序向引擎提交全部输入值。`inputA`、`inputB` 和旧波形字段继续保留，作为示例电路兼容投影；新增输入默认值为 0。

## 后果

- 输入设置可以展示和切换任意数量的 Input Component。
- 结构变更后，输入值按稳定编辑器 ID 保留，不依赖引擎 ID。
- 当前输出读取仍使用第一个 Output Component，AND 示例的仿真约束保持不变。（已由下文取代。）

## 后续变更

2026-09-17 在 Phase 3 切片 3 落地：工作区改为读取文档中全部 Output 元件，每个 Output 从自己的接收端读取信号，不再假设只有一个 Output。同一改动删除了 AND 示例的专用仿真投影——工作区不再有 `LabIds`、`DemoRuntimeBindings` 与「至少两个 Input 加一个 AND 门」的形状约束，改为由 `loadCircuit(document)` 接收整份文档并推导运行时绑定，示例本身只是普通的文档数据，与用户搭建的电路走同一条路径。

本决策关于输入绑定的部分不变。`inputA`、`inputB` 与波形字段仍作为兼容投影保留；输入值的键从示例专用的 `a` / `b` 统一为编辑器 Component ID，这一变化与本文档最初的定义一致。

2026-09-18 在 Phase 4 切片 4 落地：运行控制组接入工具栏，输入按钮的可用性从「仿真可运行」改为「可以切换 Input」——**运行中也必须能切换**，那次切换只提交 `set_input`，由下一次 Tick 带上新值；停止或暂停时仍沿用「提交后立刻 settle、画面即时更新」。同一改动为运行控制选定键位并登记下表。

## 键位表

编辑器级快捷键集中登记在这里，新增绑定前先查表避免冲突。解析器在 `src/editor/keyboard.ts`，全局分发在 `App.vue`，画布内的按键由 `CircuitCanvas.vue` 处理；被 Electron 默认加速键占用的组合在 `electron/main.cjs` 的 `before-input-event` 里处置。

| 按键 | 意图 | 作用域 |
| --- | --- | --- |
| `Ctrl/Cmd + Z` / `Ctrl/Cmd + Shift + Z` | 撤销 / 重做 | 全局 |
| `Ctrl/Cmd + D` | 复制选中元件 | 全局 |
| `Ctrl/Cmd + =` / `-` / `0` | 放大 / 缩小 / 适合窗口 | 全局 |
| `F5` | 开始连续运行；已暂停时从暂停处继续 | 全局 |
| `F6` | 暂停连续运行 | 全局 |
| `F7` | 单步，精确推进一个 Tick | 全局 |
| `Delete` / `Backspace` | 删除选中对象 | 全局 |
| `Escape` | 取消当前最上层状态 | 全局与画布 |
| `Tab` / `Shift + Tab` | 在画布对象间移动焦点 | 画布 |
| `Shift + 方向键` | 平移视口 | 画布 |
| `方向键` | 移动焦点 / 微调 Route 手柄 | 画布 |
| `Alt + 方向键` | 移动聚焦的 Component | 画布 |
| `F10 + Shift` / `ContextMenu` | 打开画布分级菜单 | 画布 |
| `Space` | 布线草稿中切换轴向 | 画布 |

运行控制占用连续的功能键簇，与既有绑定没有交集：`F5` 同时承担「开始」与「继续」，因为两者是同一个「让电路跑起来」的意图，由调用方按当前运行态分派；`F6` 是它的逆操作，`F7` 与工具栏的「单步」一一对应。三者都不依赖修饰键，因此在画布聚焦时同样可用。
