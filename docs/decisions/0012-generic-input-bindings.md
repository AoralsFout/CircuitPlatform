# ADR 0012：输入设置按编辑器元件绑定驱动

## 状态

已确认

## 背景

输入设置最初只服务于固定 AND 示例，因此工作区只保存 `inputA` 和 `inputB`，编辑器侧也只取前两个 Input Component。用户在画布中添加第三个输入后，它既不会出现在输入设置中，也不会被提交给仿真引擎。

## 决策

工作区使用由编辑器 ID 索引的输入绑定集合。重新绑定仿真时收集所有类型为 `input` 的 Component，并在每次求值前按绑定顺序向引擎提交全部输入值。`inputA`、`inputB` 和旧波形字段继续保留，作为示例电路兼容投影；新增输入默认值为 0。

## 后果

- 输入设置可以展示和切换任意数量的 Input Component。
- 结构变更后，输入值按稳定编辑器 ID 保留，不依赖引擎 ID。
- 当前输出读取仍使用第一个 Output Component，AND 示例的仿真约束保持不变。（已由下文取代。）

## 后续变更

2026-09-17 在 Phase 3 切片 3 落地：工作区改为读取文档中全部 Output 元件，每个 Output 从自己的接收端读取信号，不再假设只有一个 Output。同一改动删除了 AND 示例的专用仿真投影——工作区不再有 `LabIds`、`DemoRuntimeBindings` 与「至少两个 Input 加一个 AND 门」的形状约束，改为由 `loadCircuit(document)` 接收整份文档并推导运行时绑定，示例本身只是普通的文档数据，与用户搭建的电路走同一条路径。

本决策关于输入绑定的部分不变。`inputA`、`inputB` 与波形字段仍作为兼容投影保留；输入值的键从示例专用的 `a` / `b` 统一为编辑器 Component ID，这一变化与本文档最初的定义一致。

2026-09-18 在 Phase 4 切片 4 落地：运行控制组接入工具栏，输入按钮的可用性从「仿真可运行」改为「可以切换 Input」——**运行中也必须能切换**，那次切换只提交 `set_input`，由下一次 Tick 带上新值；停止或暂停时仍沿用「提交后立刻 settle、画面即时更新」。同一改动为运行控制选定键位并登记下表。

2026-09-18 在 Phase 4 切片 2 落地：重置接入工具栏与键盘，键位取运行控制功能键簇的下一个空位 `F8`，与既有绑定没有冲突。它与「单步」并列，把仿真恢复到初始状态而不是推进它。

2026-09-18 在 Phase 4.5 切片 5 落地：输入设置改为**按位**编辑，本决策与下面的键位表随之扩充。

每个 Input 元件按位展开成方形按钮、每行八列，元件标签在位按钮组上方；1 位 Input 与多位 Input 共用这一套视觉，只有按钮个数不同。左键在 `0` 与 `1` 之间切换，右键把该位设为 `X`，按钮组可以展开收起——展开状态是纯视图状态，不进文档、不进历史记录。左键的规则与改造前「整块切换一个 1 位输入」的 `=== "1" ? "0" : "1"` 同源，只是作用范围缩到了一位，因此 `X` 位被点一下就变成 `1`。

键盘等价路径是位按钮组本身：`Space` 与 `Enter` 走原生按钮的激活语义完成切换，组内导航与设为 `X` 由 `resolveInputBitKeyboardAction` 判定，组因此是一个带 roving tabindex 的可聚焦按钮组。这三个键位登记在上表，作用域限定为输入设置：`方向键` 与画布上的同名绑定按焦点位置分开，`X` 带修饰键时一律让位给全局与画布的组合。

输入取值随之从整值 `0` / `1` 变为**逐位文本**（长度等于端口声明的位宽，最左是最高位），提交经 `set_input` 走与改造前同一条路径。Phase 4 的运行中语义不变：停止或暂停时切换立即求值，连续运行中只提交 `set_input`，由下一次推进带上新值。

2026-09-18 在 Phase 4.5 切片 6 落地（issue #31）：**波形不再是旧字段的拷贝。** `WaveformPoint` 从 `{step, a, b, output}` 改为 `{step, signals}`，一次推进记录的是这一拍全部端口读数的快照，键为 `${editorComponentId}:${portId}`，行由场景投影生成。`inputA`、`inputB` 与 `outputValue` 仍作为示例电路与画布的兼容投影保留，但波形已经不再依赖它们，本文档开头所说的「旧波形字段作为兼容投影保留」到此结束。

2026-09-19 在 Phase 5 落地（issue #36）：文件操作键位 `Ctrl/Cmd + S`（保存）与 `Ctrl/Cmd + Shift + S`（另存为）登记进上表。两者按既有的窗口级处理路径直达渲染进程——应用菜单已移除，没有默认加速键需要拦截。这两个组合键是唯一的例外：**焦点在输入控件里时同样生效**，因为文件操作在控件内没有本地含义，而且错过保存的代价由用户的整个下午承担。保存与另存为的行为语义（覆写、身份切换、脏标记）见规格 #34 与项目文件的 ADR。

2026-09-19 在 Phase 5 落地（issue #37）：`Ctrl/Cmd + N`（新建）与 `Ctrl/Cmd + O`（打开）登记进上表，沿用 #36 的同一条取舍——焦点在输入控件里时同样生效，文件操作键位保持一组一致的例外。两者在文档置脏时先确认（沿用清空画布的确认交互，Esc 可取消），确认后才进入打开对话框或空文档。

2026-09-19 在 Phase 5 落地（issue #38）：顶栏新增「最近项目」下拉入口，列出最近的 Project（显示名 + 路径提示），点击条目经与文件对话框打开相同的加载路径直接打开。入口本身不新增全局快捷键：触发按钮与条目都是原生按钮，`Tab` 按文档顺序可达、`Enter`/`Space` 原生激活；菜单内补两个惯用键位并登记进下表——`方向键` 在条目间循环移动焦点，`Esc` 关闭菜单并把焦点还给入口按钮。`Esc` 在菜单内只关菜单，不冒泡给窗口级的取消处理，避免顺手清掉画布上的选择或确认框。列表为空时整个入口不渲染，不出现空菜单。

## 键位表

编辑器级快捷键集中登记在这里，新增绑定前先查表避免冲突。解析器在 `src/editor/keyboard.ts`，全局分发在 `App.vue`，画布内的按键由 `CircuitCanvas.vue` 处理，输入设置内的按键由 `WorkspaceSidebar.vue` 处理；被 Electron 默认加速键占用的组合在 `electron/main.cjs` 的 `before-input-event` 里处置。同一按键在不同作用域下含义不同时，按焦点所在的作用域分派。

| 按键 | 意图 | 作用域 |
| --- | --- | --- |
| `Ctrl/Cmd + Z` / `Ctrl/Cmd + Shift + Z` | 撤销 / 重做 | 全局 |
| `Ctrl/Cmd + N` | 新建空文档；文档置脏时先确认 | 全局（含输入控件） |
| `Ctrl/Cmd + O` | 打开项目文件；文档置脏时先确认 | 全局（含输入控件） |
| `Ctrl/Cmd + S` | 保存当前文档；未保存过的文档转入另存为 | 全局（含输入控件） |
| `Ctrl/Cmd + Shift + S` | 另存为，总是询问位置；成功后文档身份切换为新路径 | 全局（含输入控件） |
| `Ctrl/Cmd + D` | 复制选中元件 | 全局 |
| `Ctrl/Cmd + =` / `-` / `0` | 放大 / 缩小 / 适合窗口 | 全局 |
| `F5` | 开始连续运行；已暂停时从暂停处继续 | 全局 |
| `F6` | 暂停连续运行 | 全局 |
| `F7` | 单步，精确推进一个 Tick | 全局 |
| `F8` | 重置，把仿真恢复到初始状态 | 全局 |
| `Delete` / `Backspace` | 删除选中对象 | 全局 |
| `Escape` | 取消当前最上层状态 | 全局与画布 |
| `Tab` / `Shift + Tab` | 在画布对象间移动焦点 | 画布 |
| `Shift + 方向键` | 平移视口 | 画布 |
| `方向键` | 移动焦点 / 微调 Route 手柄 | 画布 |
| `Alt + 方向键` | 移动聚焦的 Component | 画布 |
| `F10 + Shift` / `ContextMenu` | 打开画布分级菜单 | 画布 |
| `Space` | 布线草稿中切换轴向 | 画布 |
| `方向键` | 在位按钮组内移动焦点（左右逐位、上下跨行，两端停住不绕回） | 输入设置 |
| `Space` / `Enter` | 切换聚焦位的 `0` / `1` | 输入设置 |
| `X` | 把聚焦位设为 `X` | 输入设置 |
| `方向键` | 在最近项目条目间循环移动焦点（两端绕回） | 最近项目菜单 |
| `Escape` | 关闭最近项目菜单，焦点回到入口按钮 | 最近项目菜单 |

运行控制占用连续的功能键簇，与既有绑定没有交集：`F5` 同时承担「开始」与「继续」，因为两者是同一个「让电路跑起来」的意图，由调用方按当前运行态分派；`F6` 是它的逆操作，`F7` 与工具栏的「单步」一一对应，`F8` 与「重置」一一对应。四者都不依赖修饰键，因此在画布聚焦时同样可用。
