# ADR 0019：tick 由协议显式驱动、只有 `0 → 1` 采样、结构变更按元件身份保留状态

## 状态

已确认

## 背景

[ADR 0004](0004-json-lines-engine-session.md) 把「结构变化后重建 `Simulation` 快照」定为第一版简单且可解释的运行时规则，并在结果里写明「后续需要在引入时序逻辑前明确更细的 reset 语义」。只有组合逻辑时，重建的代价是「输入被重置」这种可以忍受的小事；引入 D Flip-Flop 之后，它变成「删掉一个无关的 Output 也会把触发器里保存的位清空」。Phase 4 必须回答这个问题。

同一阶段还要回答另外两个问题：时间怎么推进，以及 D Flip-Flop 在什么时刻采样。

## 决策

### 一、tick 由协议上的显式请求驱动，引擎里没有时间

引擎只提供两个纯粹的、同步的动作：`tick` 推进一步，`reset` 回到刚创建时的状态。引擎侧因此没有定时器、没有后台线程、没有需要推断的「当前是否在跑」，每一步都能用「一行 JSON 进、一行 JSON 出」复现，时序语义也就能在没有 Electron 的情况下被测试。

连续运行完全落在前端：开始就是反复发 `tick`，暂停就是不再发，继续就是把没发完的接上。下一次推进在收到上一次响应**之后**才排定，因此不会有两个推进同时在飞，引擎变慢时自动降速。

`tick` 的顺序固定为六步，顺序本身就是语义：记录每个 DFlipFlop 在 `clock` 端口上的前值 → 翻转每个 Clock → 组合求值到稳定 → 比较前值与当前值完成边沿采样 → 再求值一次 → 步数自增。先求值再判边沿、判完边沿再求值，是「时钟可以经组合逻辑传入」这条规则能成立的原因。

### 二、只有 `0 → 1` 算上升沿，且判定只看端口

`0 → 1` 采样，`1 → 0` 不采样，任何一端是 `X` 的跳变也不采样。这是对路线图「值相对上一 tick 发生变化时采样」的收窄：真正的 D Flip-Flop 是边沿触发而不是电平变化触发，而 `X → 1` 无法构成可靠的上升沿——上一拍可能本来就是 1。收窄的连带结果是 **Clock 的 `out` 初值必须是 `0` 而不是 `X`**，否则第一次跳变是 `X → 1`，永远判不出上升沿。

判据只读 `clock` 端口的前后值，与元件类型无关。时钟可以来自 Clock 元件、`set_input` 驱动的 Input 元件，或经过组合逻辑的门控时钟，走的是同一条判定。[ADR 0014](0014-subcircuit-by-reference-flattened-simulation.md) 规定的「Subcircuit 不允许内部出现 Clock、展平后外部时钟接到内部 Input 元件上」因此不需要任何特殊处理。

判边沿所需的前值跨 tick 保留，而不是每次推进时现读：驱动 `clock` 端口的可能是 Input 元件，它的电平变化发生在两次 tick 之间，现读会漏掉这类边沿。

### 三、结构变更按元件身份重新推导状态，不再重建 Simulation

`Simulation` 不再按值持有一份 `Circuit` 副本，而是持有引用。结构变更后按元件身份重新推导仿真状态：

- `PortId` 仍然存在的端口保留当前值；
- 消失的端口连同它的值一起丢弃；
- 新出现的端口按初始值建立（Clock 的 `out` 为 `0`，其余输出为 `X`）；
- 仍然存在的 DFlipFlop 保留它的 `q` 与它在 `clock` 端口上的前值。

按身份保留是安全的，因为**元件身份单调递增、永不重用**——同一个 id 不会换一个元件回来。已推进的步数不归零：结构变更不是重置。

**`reset` 与结构变更保留状态是两件独立的事。** `reset` 把整个仿真恢复成刚创建时的状态：全部输出回到初始值、Clock 回到 `0`、每个 DFlipFlop 的 `q` 回到 `X`、步数归零，`Circuit` 结构不变。结构变更保留状态，`reset` 清空状态，两者因此可以分别测试。

前端在结构修改后把运行切到 `paused` 并保留已积累的时序状态，由用户按「继续」接着跑，不自动恢复运行。工作区只在自己收到的绑定真的改变了拓扑时才当作结构修改——移动元件、改 Route 与改线色不会分配新的引擎身份，不该停掉正在跑的仿真。

## 未采用的方案

### 保留按值副本，另加一条「重新采纳电路」的路径

不采用。两条路都能实现「不再重建」，但持有引用让「状态表描述的是当前电路」成为结构上的不变量，而不是一条需要每次记得调用的约定；引擎里也因此不再有任何一处会复制整份 `Circuit`。代价的实测比预期小：所有既有构造点传的都是左值 `Circuit`，构造签名换成 `const Circuit&` 后一处都不用改。为防止绑定临时值造成悬空引用，右值构造被显式删除。

### 让引擎侧拥有定时器

不采用。引擎主循环是阻塞式逐行读 stdin；加定时器需要非阻塞读或独立线程，会让「同样的输入序列必然产生同样的输出序列」这条可复现性失效，也让时序语义无法脱离 Electron 测试。

### 让时钟只有 Clock 元件才能驱动

不采用。判据一旦绑到元件类型上，展平后的 Subcircuit（外部时钟接到内部 Input 元件）与门控时钟都会失效，而它们在用户看来与 Clock 元件没有区别。

## 后果

- 结构修改不再是破坏性操作：删掉一个无关元件不会丢掉触发器里保存的位；
- `Simulation` 引用外部的 `Circuit`，因此那个 `Circuit` 必须比它活得久，且调用方必须在修改电路之后、下一次求值之前通知它重新推导状态（`reconcile`）。忘记通知的后果是状态表缺掉新元件，而不是静默使用过期结构；
- 已删除元件的端口与时钟前值需要主动裁剪，否则会在状态表里留下永远不可达、也不会自行释放的残留。裁剪在 `reconcile` 里一次做完；
- 引擎侧没有「当前时间」概念，波形、步数与运行控制全部由前端记账；
- 本阶段不做时序状态的保存与恢复。引擎进程重启仍是从零开始的新进程，重启后由前端重新推送文档（这条推送路径属于 Phase 5）。

### 已知限制：撤销恢复的 D Flip-Flop 回到 `X`

撤销删除会用**新的引擎身份**重建被删元件（[ADR 0007](0007-editor-session-and-stable-editor-ids.md) 的补偿事务，「旧 engine ID 永不重新绑定」），因此按身份保留救不回撤销恢复的 D Flip-Flop：它是一个新元件，`q` 回到 `X`，需要在时钟上再走一个上升沿才会重新采样。

这是既有设计的直接后果，本决策明确接受，不为此改变 ADR 0007。它与「删掉一个无关元件不丢状态」不冲突：前者改的是目标元件自己的身份，后者不动目标元件的身份。
