# ADR 0021：项目文件 v1、路径身份与整体替换

## 状态

部分继续适用。普通 Project 的路径身份、文件原子写入和整体替换事务继续有效；v1 文件结构与按路径保存 Subcircuit 引用由 [ADR 0027](0027-embedded-subcircuit-snapshots.md) 的严格 v2 内嵌定义格式取代。

## 背景

Phase 5 之前磁盘上没有任何项目文件：电路、布局与输入激励都活在工作区内存里，关窗即失。波形只记录用户发起的推进，连续运行不产生历史。编辑器文档推送到引擎的路径已经存在，但只被启动时的 AND 示例用过。路径身份的规则没有定死，而后续阶段（5.5 子电路按相对路径引用、5.6 文档按路径去重）都要以它为基础。

## 决策

**文件格式 v1**：项目文件是 UTF-8 JSON，扩展名 `.circuit.json`，根对象是 `{version, circuit}`。保存是全量覆写：先写临时文件、成功后原子替换，写到一半的失败不损坏目标文件。序列化与校验是渲染层的纯模块，主进程只做对话框与文件 IO——校验规则只有一份实现。

**Editor ID 写入文件并作为文件内唯一身份**。元件与连接的文件内身份就是编辑器现有的稳定 Editor ID，连接端点用它引用元件，加载后沿用同一套身份、不重新生成。文件内的引用只有一套 ID 空间，与撤销历史、信号键空间共用。文件内的连接 ID 同样必须唯一；端点引用不可解析属于文件结构非法，整体拒绝加载。

**端口清单只为数据驱动元件写入**。Input / Output 的位宽、拆线器 / 合线器的位区间清单是用户可改的数据，必须落盘；内置逻辑门不写清单，由引擎回退到内置定义。文件里的清单是缓存：加载时随 `add_component` 送达，`component_added` 回传的清单仍是权威并覆盖缓存（[ADR 0020](0020-port-list-is-the-only-authority.md) 不变）。

**元件记录带按类型扩展的数据袋 `data`**。v1 保存 Input 的当前值，Phase 5.5 另保存 Subcircuit 的相对引用、缓存端口清单和可选端口顺序。时序状态（DFlipFlop 的 `q`、时钟相位、tick 计数）不进文件：它是仿真状态，不是电路定义。

**路径身份是词法规范化后的绝对路径**。规范化无 IO：解析为绝对路径、统一分隔符、消除 `.` 与 `..` 段、Windows 盘符统一大小写；比较在 Windows 上大小写不敏感、POSIX 上敏感；显示保留原始写法；不解析符号链接——同一实体经由不同链接的路径被视为不同身份。最近项目去重与 Phase 5.6 的文档身份共用这条规则。

**打开的整体替换先推新、成功后才移除旧**。打开项目时若工作区已有电路，先推送新文档（引擎身份单调递增，两份电路短暂共存不冲突），全部成功后移除旧电路元件并整体替换绑定；推送失败则补偿移除新建结构、恢复旧绑定——旧文档在引擎里的结构从头到尾没被碰（[ADR 0019](0019-tick-driven-by-protocol-and-state-kept-by-identity.md) 的身份单调性是前提）。

**波形由仿真状态产生、按 tick 逐拍记录**。连续运行每一拍追加一点，历史上限 1,000 点、超出丢弃最旧；重置清空历史；引擎重建随旧进程时间线一并清空。波形历史是会话状态，不进项目文件；重新打开后行由文档重新推导，首点记录加载后的首次求值读数。

**推送时延预算**：500 元件 / 1,000 连线的完整推送（含加载后首次求值）均值 ≤ 6 秒，由端到端回归在真实引擎上断言。规格 #34 原定价 3 秒（P95），依据是普通门形状的实测约 1.6 ms/条；落地实测发现恰好凑出该规模的形状必须以 8 输入合线器为连接目标，位区间端口上的连接校验使每条连线成本翻倍（约 3.2 ms/条），叠加机器状态 ±40% 的波动后同口径实测均值 3.8 秒。按规格「时延不达标时首先复核口径」的预案重定为 6 秒，实测与口径记录于[性能基准](../testing/performance-benchmark.md)。

## 结果

- 用户可以保存、另存为、打开与新建项目，重新打开后结构、布局、激励与组合读数和保存前一致；时序状态从 `X` 开始是明确接受的限制；
- 打开、重载与引擎重启的重建共用同一条推送路径，Phase 5.5 / 5.6 不再实现第二遍；
- 同一文件的不同写法被识别为同一份 Project，「同一份 Project 是否已打开」从此有唯一答案；
- 引擎与协议零改动，C++ 侧无回归面。

## 未采用的方案

- **文件自建一套数字身份、加载时重映射到编辑器 ID**：两套 ID 空间永远要做一次翻译，而文件内部引用本来就需要一套身份；沿用 Editor ID 让撤销历史与信号键空间免费兼容。
- **存渲染 Route 而非语义 Waypoint**：Route 依赖端点位置，元件挪动后存下来的 Route 就是过时的几何；语义 Waypoint 加载后由端点加折点重新推导，与投影层对旧文档的回退是同一条规则。
- **输入值不进文件**：重新打开后激励归零，「仿真结果与保存前一致」字面不成立；搭测试激励的用户预期是原样恢复。
- **序列化放主进程**：主进程是 CommonJS 且无测试基建，校验规则会写出第二份实现。
- **整体替换先删旧再推新**：推送失败会毁掉当前文档，违反「加载失败不丢失当前编辑器状态」。
- **推送提速引入批量请求**：实测瓶颈在引擎逐条连接处理而不在往返，批量请求是引擎与协议改动，破坏本阶段零改动的收益；时延不达标时先复核口径。

## 后续变更

- Phase 5.5 已把 Subcircuit 的引用路径、缓存端口清单与显式端口顺序放进元件记录的 `data` 袋，格式骨架不变；
- Phase 5.6 的文档身份沿用本文的路径规范化规则；未保存文档以临时身份占位，保存时切换为路径。
