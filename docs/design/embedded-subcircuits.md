# 内嵌子电路设计

## 状态与依据

- 状态：设计已确认；尚未实现。
- 决策：[ADR 0027](../decisions/0027-embedded-subcircuit-snapshots.md)。
- 实施规格：[Issue #67](https://github.com/AoralsFout/CircuitPlatform/issues/67)。
- 取代的现有行为：按路径引用、打开时读取子文件、按源文件保存事件显示 `needsReload`、下钻打开源文件。展平仿真与每个放置位置独立的时序状态继续使用。

## 用户可见的模型

一个 Project 保存顶层 Circuit 和若干导入的 Subcircuit 定义。定义有父工程内稳定身份和显示名称；画布上的 Subcircuit Component 记录定义身份。一个定义能被放置多次，结构共享，仿真状态互不影响。每次“从文件导入”建立新定义；“再次放置”复用树中已有定义。

导入复制源 Project 的顶层 Circuit，以及从该 Circuit 实际可达的内嵌定义。每次导入的递归定义自成一组；即使父工程已有来自同一文件的 B，导入 A 时也不复用或更新已有 B。源 Project 的闲置定义不复制。导入内容包含保存过的电路结构、布局、标签、输入值和 Port 顺序，不包含仿真状态、波形、撤销历史或视口。导入后父工程不保存源路径，也不读取源文件来打开、仿真、保存或恢复；源文件修改、移动或删除均不改变已有定义。

导入定义的 Circuit 只读，显示名称可单独修改。左侧新增“子电路”页，按直接导入的定义及其递归依赖展示树；同名定义显示序号，节点显示使用数量。未被放置的直接导入定义继续留在树中。树节点与画布上的子电路元件打开父工程内的只读标签。标签仅展示结构，不建立独立仿真；父电路选中某次放置位置时，现有检查器继续展示该处内部的实时信号。

只读标签以父文档运行时键和定义 ID 去重，直接读取父文档内存定义，不把定义当作可编辑 Project 打开。树节点回车或“查看定义”、画布元件回车或双击以及定义中的嵌套查看按钮均可下钻；标签栏可用方向键切换，返回父电路为原生按钮。定义被删除时已打开标签保留身份并显示“定义已删除”，撤销后恢复内容。父文档关闭时一起关闭其定义标签，普通 Project 标签仍按路径去重。

“子电路”页与现有平铺“层级”页并列。树从 `libraryRoots` 出发，按定义中的使用处展开嵌套依赖；使用数统计顶层电路和所有定义内的静态引用，缺失定义以诊断节点展示。节点选择及“仅导入”“再次放置”“改名”使用原生按钮和表单，键盘可逐项操作。仅导入与改名通过工作区投影事务提交，即使顶层画布没有任何元件，也进入保存、撤销和重做。再次放置从父工程保存的定义读取接口，不访问源文件。

画布中的 Subcircuit 标题只在呈现时隐藏 `.circuit.json` 文件扩展名：`ALU.circuit.json` 显示为 `ALU`，`ALU.circuit.json (2)` 显示为 `ALU (2)`。所有非画布位置（包括左侧视图、只读标签与检查器）仍显示完整名称；手工改名后没有该扩展名的名称保持原样。实现应从保存的显示名称推导画布文本，不修改定义身份或持久化名称。

## 文件与模块接口

新 `.circuit.json` 文件使用精确版本 `2`。旧版文件在普通打开和导入时均明确拒绝，不自动迁移。建议的逻辑结构为：

```text
Project v2
├─ version: 2
├─ circuit: 顶层 Circuit 及编辑器数据
├─ definitions: 以父工程内稳定 ID 索引的定义表
│  └─ 每个定义含显示名称、Circuit 及编辑器数据
└─ libraryRoots: 直接导入、显示在树根的定义 ID

Subcircuit Component.data
├─ definitionId: 父工程内的定义 ID
├─ cachedPorts: 定义缺失时仍可显示的接口
└─ portOrder: 可选的显式 Port 顺序
```

定义表内的引用只使用 `definitionId`，不保存源路径。解析器校验 ID 唯一性、Port 数据、定义引用环及整体形状；缺失定义与悬空 Connection 是可保存的明确状态。旧版 `ProjectFileData` 的 `reference` 字段、相对路径重定位和打开时文件读取不进入 v2。另存为不需要改写内嵌定义。导出某个定义时，将它的 Circuit 作为新 Project 的顶层 Circuit，并仅携带可达的下层定义。

文件格式与定义图操作应形成纯 TypeScript 模块：输入已解析的 Project 数据和用户选择，输出完整候选快照、诊断与受影响使用处。模块内部负责可达闭包、ID 重映射、循环与接口校验、端口匹配和更新影响计算。Electron 只负责选文件、读取、写入；Vue 只负责呈现和收集确认。展平模块消费内存中的定义图，不通过 ProjectReader 访问磁盘。编辑器会话在确认后把定义图、可见文档、扁平投影和引擎绑定作为一帧历史提交，失败时保留旧状态。

## 操作与状态

| 操作 | 结果 |
| --- | --- |
| 导入并放置 | 读取已保存的 v2 Project，复制其可达闭包，创建新定义并在顶层 Circuit 放置元件；父工程无需预先保存。 |
| 仅导入 | 创建相同的定义快照，但不放置元件。 |
| 再次放置 | 从树选已有定义，只新增引用它的 Component。 |
| 重新导入 | 用户重新选文件；保留所选定义 ID 与显示名称，整体替换其 Circuit 和下层闭包。旧下层定义移除，新下层定义取得新 ID。 |
| 删除定义 | 未被使用时直接删除；被使用时先列出使用位置并要求再次确认。确认后保留使用处、缓存 Port 与 Connection，并标记定义缺失。 |
| 修复定义缺失 | 可选择已有定义或从文件导入新定义；可编辑顶层中的不兼容连接变为悬空，只读嵌套 Circuit 内不兼容则拒绝。 |
| 导出定义 | 从树中选直接或嵌套定义，选择保存位置后将它的 Circuit 提升为独立 v2 Project 的顶层，仅附带实际可达的下层定义；父工程、撤销历史和仿真状态不变。 |

导出沿用普通 Project 的保存对话框与原子文件写入通道。取消、写盘失败、所选定义缺失都会在子电路页显示结果；禁止将导出目标设为当前父 Project 路径。导出文件的 `libraryRoots` 为空，因为下层定义已由新的顶层 Circuit 引用。导出文件打开后可独立编辑、仿真与保存；这些修改不会自动更新父 Project，用户须从文件显式重新导入。

重新导入先完整读取、校验和计算影响。读取失败、格式非法或成环时，旧定义、仿真结构及历史不变。若只更新嵌套 B 会使只读上层 A 的内部 Connection 悬空，也拒绝更新，并提示重新导入 A。若顶层 Circuit 的 Connection 会悬空，先列出受影响 Port 和 Connection，请用户确认；匹配条件为 Port 名称、方向和位宽完全相同。导入源文件本身已有定义缺失或悬空 Connection 时允许导入并显示警告，可运行部分继续仿真。

重新导入和确认删除各是一帧可撤销历史。被重建的展平子树从初始仿真状态开始，未受影响部分保持状态，撤销不倒转整个仿真时间。重新导入时所选定义的只读标签显示新内容；旧下层定义或已删除定义的标签显示“定义已删除”，撤销后可以恢复。定义缺失的使用处及其连接可以随父 Project 保存并重新打开；仿真跳过缺失子树及穿过它的 Connection。

删除候选先列出所选定义在顶层及其他定义内的具体使用位置。删除仍被使用的定义需要确认对话框；没有使用处的直接导入定义立即提交。清理下层时保留被其他根、顶层使用处或剩余定义引用的定义。删除提交保留原 Component 的定义 ID、缓存 Port 与 Connection；只读标签按原 ID 显示缺失状态，撤销后恢复。只读电路中的嵌套定义若已缺失，“查看定义”入口禁用并用文字说明原因。

## 验收场景

1. 导入 A→B、保存父工程、移动或删除 A 与 B 的源文件，再打开父工程；树、画布和端口与保存时一致，组合逻辑按已保存的输入值求值，时序状态按既有规则从初始值开始。
2. 同一父工程两次从同一文件导入形成两个独立定义；从树中再次放置某一定义则共享其结构，多处 DFlipFlop 状态相互独立。
3. 父工程已有旧 B 时导入依赖新版 B 的 A；旧 B 不变化，A 使用导入时的新版 B。源工程保存新改动不会触发父工程的 stale 提示。
4. 重新导入失败保持旧快照；成功更新同一定义的所有使用处。顶层端口变化先预告并产生可修复的 DanglingConnection；嵌套局部更新导致只读上层断线时拒绝。
5. 确认删除仍被使用的定义后，缺失使用处与连线可保存、重开、撤销和修复；其他分支继续仿真。
6. 只读标签可查看完整结构，不能编辑或独立仿真；导出的 v2 Project 可编辑，编辑结果只有重新导入后才影响父工程。
7. v1 Project 在打开和导入时得到明确的不支持版本诊断；v2 项目另存为跨目录或跨磁盘后不改变内嵌电路。
8. 画布上的 `ALU.circuit.json` 与 `ALU.circuit.json (2)` 分别显示 `ALU` 与 `ALU (2)`；所有非画布位置保留完整名称。
