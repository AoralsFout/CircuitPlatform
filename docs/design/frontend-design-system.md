# CircuitPlatform 前端设计规范

## 文档状态

- 版本：0.1
- 状态：已确认方向，待随组件实现迭代
- 适用范围：`apps/desktop` 的 Vue 桌面应用
- 最后更新：2026-09-17

## 1. 产品定位

CircuitPlatform 是面向初学者的数字电路仿真工作台。界面需要具备专业电路工具的结构和可信度，同时通过清晰层级、直白文案和即时反馈，帮助用户理解“输入如何影响输出”。

设计语言定位为：**引导式数字电路工作台**。

它借鉴实验仪器台和工程图纸的视觉语汇，但不追求复杂 EDA 软件的密度。中央画布是主要工作区，信号连线是主要记忆点，颜色只表达明确的状态含义。

## 2. 体验原则

1. **先看懂，再深入**：默认界面优先展示名称、值、关系和下一步动作；端口 ID、组件 ID 和引擎数据按需展开。
2. **结构优先**：节点、端口、连线和波形服务于电路关系，不使用无意义的卡片或装饰。
3. **状态可见**：仿真、保存、引擎连接、连接校验和错误状态都必须有持续且可理解的反馈。
4. **信号是主角**：高电平、低电平和未知状态在节点、端口、连线和波形中保持一致。
5. **动作说人话**：使用“单步”“添加元件”“连接端口”等用户能直接理解的动词。
6. **渐进式专业能力**：初学者默认路径保持简单，高级检查和诊断能力仍然可达。
7. **可恢复操作**：删除、清空、加载和保存失败都必须提供恢复或继续操作的路径。

## 3. 核心工作流

```text
启动：空状态与最近项目
  ↓
加载示例或新建 Project
  ↓
修改输入
  ↓
观察节点、连线和输出变化
  ↓
按需展开波形和详细属性
  ↓
添加、连接并保存自己的电路
```

Phase 3 期间首次启动会自动加载一个可运行的 AND 示例（[ADR 0005](../decisions/0005-frontend-design-language.md)）。Phase 5 引入项目文件与最近项目后，启动进入空状态（见第 10 节），AND 示例降为「加载示例」入口——这条改变记在 [roadmap](../roadmap.md) 的 Phase 5。示例完成第一次求值后，画布提示用户切换输入 A 或输入 B。

## 4. 信息层级

### 默认层

面向所有用户，必须直接显示：

- 元件名称；
- 输入和输出端口；
- 当前信号值 `0 / 1 / X`；
- 当前仿真状态；
- 当前可执行的主要操作。

### 详情层

选中对象或展开检查器后显示：

- 元件类型；
- 端口名称和连接关系；
- 组件 ID；
- 仿真状态；
- 波形数据；
- 引擎诊断信息。

详情层不能替代默认层，也不能要求初学者理解内部协议字段才能完成基础任务。

### 5.4 状态语义

| 状态 | 颜色 | 附加表达 |
| --- | --- | --- |
| 高电平 `1` | `--color-signal-high` | 实线、数值 `1`、轻微光晕 |
| 低电平 `0` | `--color-signal-low` | 实线、数值 `0` |
| 未知 `X` | `--color-signal-unknown` | 虚线或点划线、数值 `X` |
| 就绪 / 成功 | `--color-status-success` | 状态点或结果文字 |
| 警告 | `--color-status-warning` | 警告图标和说明 |

| 键盘焦点 / 当前选择 | `--color-focus` | 外轮廓，不能只改变背景 |

颜色不能单独承担状态表达。信号状态还必须通过文字、线型、方向或图标表达。

```css
:root {
  --font-display: "Cambria", "Georgia", serif;
  --font-body: "Bahnschrift", "Segoe UI", "Microsoft YaHei", sans-serif;
  --font-data: "Cascadia Mono", "Consolas", monospace;
}
```

| 层级 | 尺寸 | 用途 |
| --- | --- | --- |
| Display XL | 64–76px | 页面主标题 |
| Display L | 40–52px | 工作区标题 |
| Heading | 20–28px | 面板标题 |
| Body | 13–15px | 正文和操作说明 |
| Label | 10–12px | 工程标签和状态标签 |
| Data | 12–16px | 信号值、端口名和组件 ID |

规则：

- 标题可以使用衬线字体，按钮和状态不得使用衬线字体；
- 端口名、信号值和 ID 使用等宽字体；
- 中文正文使用句首大写的自然句式，不强行全大写；
- 英文工程标签可以使用大写和字距，但只作为辅助信息；
- 正文行高通常为 `1.5–1.7`；
- 重要信息不能只依靠小字号和低对比度表达。

## 7. 尺寸与布局

### 7.1 基础间距

```text
4px   最小图标间距
8px   紧凑控件间距
12px  标签和内容间距
16px  组件内部常规间距
24px  面板区块间距
32px  页面区块间距
40px+ 页面级留白
```

### 7.2 工作区

```text
应用外壳
├── 顶部项目栏
├── 工具轨道
├── 可折叠侧栏（元件库 / 层级）
└── 编辑区
    ├── 编辑工具栏
    ├── 电路画布
    └── 结果面板（输出 / 波形）
```

该结构与 [ADR 0006](../decisions/0006-editor-workspace-redesign.md) 和工作区重构的交付结果一致；侧栏底部固定节点检查器。

中央画布是主工作区。侧栏可以折叠，波形查看器默认收起。窗口缩放时优先保持画布可用空间，不让工具栏和结果面板被压缩到不可读。

### 7.3 画布术语与职责

- **画布（Canvas）**：展示和操作编辑器文档的界面区域，不等同于领域 `Circuit`，也不持有仿真规则。
- **视口（Viewport）**：画布当前可见的世界坐标范围，由平移量和缩放比例决定；视口状态独立于编辑器文档，不进入撤销和重做历史。
- **世界坐标（WorldPoint）**：Component 编辑器投影及 Wire 路径使用的稳定逻辑坐标，不随窗口尺寸和视口变化。
- **屏幕坐标（ScreenPoint）**：指针事件和实际显示使用的坐标，必须通过统一的视口变换与世界坐标互转。
- **CircuitNode**：领域 Component 在编辑器中的视觉投影，只负责展示和抛出交互意图，不是新的领域对象。
- **Wire**：领域 Connection 在编辑器中的视觉投影；路径几何属于编辑器模型，不进入领域 Connection。
- **选择（Selection）**：编辑器当前操作对象；**键盘焦点（Keyboard focus）**：当前接收键盘输入的界面元素。两者可以指向不同对象，视觉反馈不得互相替代。

画布渲染器根据编辑器快照绘制 CircuitNode、Port、Wire 和交互覆盖层，并把指针或键盘意图转换为编辑器命令。它不直接调用仿真引擎；仿真结果只是渲染输入。

## 8. 核心组件规范

### 8.1 Button

```text
Primary      高 40px，水平内边距 16px
Secondary    高 36px，水平内边距 14px
Compact      高 30px，水平内边距 10px
Icon button  32×32px 或 36×36px
```

主按钮只用于当前区域最重要的动作，第一版通常是“单步”。按钮状态必须包含默认、悬停、按下、焦点、禁用和执行中。

运行控制组的主按钮是“开始”与“继续”；两者互斥地可用，因此任何时刻都只有一个主按钮是亮的。运行态文案固定为三态，步数紧随其后：

```text
已停止 第 N 步 → 运行中 第 N 步 → 已暂停 第 N 步
```

运行中不再用按钮文案表达“执行中”，而由状态文案与状态点承担；「单步」在运行中禁用，因为它与连续运行互斥。

### 8.2 CircuitNode

节点是可操作的电路元件，不是普通卡片。

```text
最小宽度       144px
常规宽度       160–220px
最小高度       72px
内边距         14–16px
圆角           6px
边框           1px
```

推荐结构：

```text
CircuitNode
├── typeLabel
├── displayName
├── inputPorts
├── outputPorts
├── signalValue
└── statusMessage（可选）
```

端口数量由数据决定的元件（Subcircuit、拆线器、合线器）使用 [ADR 0014](../decisions/0014-subcircuit-by-reference-flattened-simulation.md) 与 [ADR 0017](../decisions/0017-paired-splitter-and-merger.md) 定义的另一套形状规则：端口间距 `32`、最小宽度 `148`、高度按端口数增长、宽度按最长端口名自适应并向上取整到网格。**它与上表的通用尺寸如何合并已经在 Phase 4.5 定下**：

- 展示定义里的 `size` 对内置元件是固定尺寸，对数据驱动的元件是**下限**；
- 数据驱动元件声明 `sizing: "by-port-count"`，实际尺寸在投影时按当前端口清单算出来：高度 = `30 × 2 + (最多一侧的端口数 - 1) × 32`，宽度 = `最长端口标注的字符数 × 8 + 24 × 2` 向上取整到 `16` 的网格，两者各自与下限取大者；
- 端口坐标仍然全部走通用排布规则，只有间距换成数据驱动的那一档，因此端口与盒子出自同一份几何。

默认的 8 位拆线器因此画成 `148 × 284`；每侧最多一个端口时下限 `84` 生效。宽度是**估算**而不是测量：投影是纯函数，不引入 DOM 文本测量；估大只会让盒子更宽，不会让标注溢出。既有元件的 `size` 与间距都原样不动，外观因此逐像素不变。

选中节点时使用焦点色外轮廓，并同步强调相邻端口和连线。节点本身不应整体变成信号色。

### 8.3 Port

```text
视觉圆点直径     10px
可操作命中区域   至少 24px
端口标签         10–11px 等宽字体
```

圆形连接锚点固定在 CircuitNode 边线上，24px 命中区域以锚点为中心跨越边线；鼠标悬浮、键盘聚焦或成为当前连接目标时，显示完整的命中区域边框。端口名称放在节点内部。画布 Port 标签只显示名称，不内联显示 `0 / 1 / X` 或悬空文字；信号与悬空状态由锚点样式、Wire 和检查器表达。端口颜色遵循信号 Token。输入和输出必须通过位置、方向和标签区分，不能只依靠颜色。

连接交互时：

- 可连接端口显示薄荷色外圈；
- 不可连接端口显示珊瑚色外圈；
- 取消连接后不留下临时线；
- 释放后立即显示连接结果；
- 非法连接必须说明原因。

### 8.4 SignalWire

连线默认使用水平、垂直和 90 度转角的正交线路，可使用轻微圆角转角，不使用大幅贝塞尔曲线作为编辑器默认样式。

每条 Wire 是一个领域 Connection 的视觉投影。它的 Route 由起点 Port、零个或多个有序 Waypoint 和终点 Port 组成：已连接端点的位置从 CircuitNode 的 Port 推导，Waypoint 使用世界坐标并保存在编辑器文档中；DanglingConnection 的失效端点继续保存最后有效世界坐标。Route 修改进入撤销和重做历史，但不得写入领域 Connection。

第一版支持在创建 Connection 时添加 Waypoint、编辑既有 Wire 的内部线段或折点，以及把悬空端点重新连接到合法 Port。直接连接 Port 的首尾终端线段固定且不可拖动。Wire 始终保持水平或垂直的正交线段；渲染圆角只是视觉效果，不改变 Route 数据。

用户可以从输入或输出 Port 发起布线，编辑器在提交时统一规范化为 `output Port → input Port`。从输出 Port 发起时创建新的 fan-out Connection；从空闲输入 Port 发起时创建 Connection；从已占用输入 Port 发起时进入重接状态；从悬空端点发起时继续编辑原 Connection。鼠标移入合法目标 Port 时显示明确的悬浮边框。重接成功前保留原 Connection，取消或失败不得造成短暂断路。

布线同时支持点击和拖拽：单击 Port 后可依次单击画布添加 Waypoint，再单击兼容 Port 完成；从 Port 拖拽并释放到兼容 Port 时快速完成，释放到空白处时放置首个 Waypoint 并转为持续的点击布线状态。两种手势使用同一个连接草稿状态机。

Waypoint 表示 Wire 上实际可见的正交折点。内部水平线段只能上下拖动，内部垂直线段只能左右拖动；内部折点移动时同步调整相邻线段和必要的相邻折点，靠近 Port 的折点受端点方向约束。直接连接 Port 的首尾终端线段不显示拖动手柄，也不会因拖动而自动插入绕行折点。

创建 Route 时，第一段默认沿 Port 朝外方向延伸，后续线段在水平和垂直轴向之间交替；布线过程中按 `Space` 切换当前段轴向。合法目标 Port 可以触发最后一个正交折点的预览。Port 外至少保留 `16` 世界单位的终端线段。

每次 Route 编辑后删除连续重复点和同一直线上的冗余中间点，并保证所有线段正交；规范化不得删除有意的回折、改选更短路径或重排用户折点。

键盘布线与指针布线使用同一状态机：`Enter` 开始或放置 Waypoint，方向键按一个网格单位移动草稿端点，`Shift + 方向键` 每次移动四个网格单位，`Space` 切换轴向，`Tab` 和 `Shift + Tab` 在合法目标 Port 间切换，`Backspace` 删除最后一个 Waypoint，`Esc` 取消草稿。聚焦目标 Port 后再次按 `Enter` 完成。

Wire 相交或重叠只表示视觉关系，不自动形成电气连接，也不创建 junction。Fan-out 继续由一个输出 Port 指向多个输入 Port 的独立 Connection 表达，即使对应 Wire 共享部分视觉路径。

移动 CircuitNode 时，已连接端点跟随 Port，用户 Waypoint 保持绝对世界坐标不变，渲染器只重新生成两端的派生正交折线；没有 Waypoint 时重新生成默认 Route。拖动期间实时预览，释放后作为一个编辑器命令提交。

CircuitNode 和 Waypoint 默认吸附到 `16` 世界单位网格，按住 `Alt` 可以临时关闭吸附；Port 位置由 CircuitNode 几何决定，不参与吸附。视口缩放可以改变网格绘制密度，但不得改变世界坐标中的吸附间距。

第一版不提供自动避障。Wire 可以穿过 CircuitNode，其视觉层位于节点层下方；这种几何重叠不改变 Connection 合法性，也不会自动移动用户 Waypoint。

```text
普通连接       2.5px 用户预设色实线，不随信号值改变
信号状态       0 / 1 / X 等宽文字沿 output → input 方向流动
悬空连接       保留线路预设色和悬空端点，不显示流动文字
选中连线       连续焦点色外描边，内层保留线路预设色
键盘焦点       连续焦点色外描边，不使用宽虚线
折点手柄焦点   手柄加粗并放大，沿用焦点色
非法草稿       焦点色虚线
```

Wire 只接受设计系统提供的少量颜色预设，不允许任意 CSS 色值。对象右键菜单修改单条 Wire 的颜色并进入编辑器撤销历史；元件库侧栏修改新建 Wire 的默认颜色，默认偏好保存在本机且不回写既有 Wire。

流动文字是信号状态的主要非颜色表达。启用 `prefers-reduced-motion` 或进入大场景降级时，线路中央显示静态 `0 / 1 / X`，不得完全移除文字状态。

### 8.5 Panel 和 Inspector

左侧默认显示元件列表。检查器是自动跟随当前选择的只读对象详情，不使用“属性”泛指结构、布局和仿真状态，也不通过右键菜单额外打开。

Component 详情：

- 元件显示名称和类型；
- 一句话行为说明；
- 当前信号；
- 各 Port 的方向、信号和连接状态。

Wire 详情：

- 起止 Port；
- 当前信号；
- 正常或悬空状态；
- Waypoint 数量。

Editor ID 只放在折叠的高级信息中。检查器不展示 position、engine ID 或生命周期；除下列例外之外没有可编辑属性，也不提供 Component 重命名。

Phase 4.5 起，Input / Output 元件的位宽和拆线器、合线器的位区间列表成为检查器的可编辑属性（[ADR 0016](../decisions/0016-strict-port-width.md)、[ADR 0017](../decisions/0017-paired-splitter-and-merger.md)），这是「第一版不引入没有实际用例的可编辑属性」的第一个真实例外。

位宽用数字输入框。位区间列表用一行文本，形如 `7:4, 3:0`：分支数量与每条分支覆盖哪几位是同一份清单的两个方面，写在一行里才能一次表达「八个 1 位改成两个 4 位」这种整体变更。形状不对（缺冒号、下界高于上界等）的输入就地还原成当前值且不提交；形状合法但违反覆盖规则的清单会提交给引擎，由它给出「越界 / 重叠 / 漏位」里具体哪一种的可展示原因，失败时列表停在提交前的值上。检查器的端口行照旧显示每个端口的位宽与当前多位读数，带位区间的端口标注写成 `out0[7:4]` 这样的形式。

### 8.6 WaveformViewer

波形默认收起，发生输出变化后提示用户可以展开。每条信号独占一行，左侧显示名称，时间轴使用等宽数字，当前时间步使用焦点色竖线。

波形必须同时使用颜色和 `0 / 1 / X` 文本表达状态。

Phase 4.5 起，波形行由场景投影生成，不再写死「输入 A / 输入 B / 输出」三行：每个 Input 元件的驱动端口、每个其它元件的输出端口，以及每个 Output 元件的接收端各占一行。行的键是 `${editorComponentId}:${portId}`，与画布、检查器共用同一套信号键空间；增删元件后行跟着变，不指向已经不存在的信号。单端口元件只显示元件名，多个待观察端口时用端口标签区分。

多位信号按二进制文本显示（`1010`、`X1X0`），使逐位 `X` 保持可见。单元格颜色只区分「全 `0`」「全 `1`」与其余：一条高低混合的总线没有单一电平，因此落到未知一档，逐位读数以文本为准。

波形历史只记录用户发起的推进——单步与输入切换各追加一点，连续运行中的自动 tick 不追加，因此运行中波形列不会增长。由仿真状态产生的逐 tick 波形属于 Phase 5，本阶段不提供。

### 8.7 添加 Component

右键画布背景打开应用内自绘的分级元件菜单，只在画布范围内屏蔽系统默认上下文菜单。菜单支持主题样式、边缘翻转、键盘导航、按名称快速定位以及可访问的 menu 语义。

菜单依次提供最近使用、输入与输出、逻辑门、时序逻辑和总线分类。最近使用最多显示 5 种元件；逻辑门分为基本门 NOT/AND/OR 与派生门 NAND/NOR/XOR/XNOR。「总线」分类在 Phase 4.5 落地，放拆线器与合线器两个条目（[ADR 0017](../decisions/0017-paired-splitter-and-merger.md)）；Phase 5.5 再加入「子电路」分类。分类清单以元件菜单的分类常量为准，本节随各自阶段落地同步更新。

拆线器与合线器放下即可用：新放置的拆线器是 8 位输入拆成八条 1 位分支，合线器与它对称。它们的端口清单由前端按这份默认配置生成并随添加请求发出——引擎对这两个数据驱动的元件没有内置定义可回退（[ADR 0020](../decisions/0020-port-list-is-the-only-authority.md)）。

菜单打开时保存右键位置对应的 WorldPoint。选择元件后以该点作为 CircuitNode 中心，默认吸附到 `16` 单位网格；按住 `Alt` 打开菜单时保留精确位置。放置不自动避让或偏移，成功后选中新节点。

右键菜单、元件库单击后放置和元件库拖放统一调用同一个添加命令。元件库单击进入待放置状态，拖放以释放点为放置位置；`Esc` 取消待放置状态。双击元件库项目不自动放到视口中心。

对象右键菜单保持精简：CircuitNode 提供复制和删除；Wire 提供编辑 Route、重置为默认 Route 和删除；Port 显示只读摘要以及开始连接或重接；既有 Waypoint 提供删除折点。布线草稿期间右键直接删除最近一个临时 Waypoint。右键对象会先选中它，只有命中画布背景时才显示元件添加菜单。

Component 显示名称使用文档内按类型递增且删除后不复用的序号，例如“输入 1”和“AND 2”；撤销恢复原名称，Editor ID 仍是稳定身份。

Component 展示定义集中在 `ComponentDefinitionRegistry`，统一提供类型、显示名称、分类顺序、图形符号、行为摘要、节点尺寸、Port 名称与布局、可用状态、禁用原因和搜索别名。上下文菜单、元件库、CanvasNode、Port 几何和检查器都读取同一份定义；领域合法性仍由协议和引擎最终确认。

新 Input 的初始值为 `0`；新 Output 和逻辑门在首次求值前显示 `X`，未连接输入 Port 显示 `X`。成功添加后重建 Simulation 快照并执行一次稳定求值；仿真错误保留合法结构并单独展示，不回滚 Component，也不把波形历史混入编辑器撤销历史。

选择元件类型后立即在目标位置显示不可交互的半透明 pending CircuitNode。引擎添加成功后转为正式节点、自动选中并更新最近使用；失败时保留类型和位置，显示重试与取消。Pending 状态不进入历史，成功添加作为一个命令进入历史。

复制 CircuitNode 只复制 Component 类型，在原节点右下方 `32×32` 世界单位处创建具有新 Editor ID 和递增显示名称的节点；它不复制 Connection、Route、选择状态或当前信号，新 Input 使用默认值 `0`。复制成功后选中新节点，并作为一个命令进入历史。

默认每次只放置一个 Component；按住 `Shift` 完成放置时继续保持同类型放置状态，每个成功添加分别进入历史，失败会暂停连续模式，`Esc` 退出。

菜单支持 `Shift+F10` 或菜单键在画布键盘焦点处打开；没有键盘光标时使用视口中心。方向键导航层级，`Enter` 选择，`Esc` 逐级关闭；输入中文名称或英文类型别名时显示单层筛选结果。菜单关闭后焦点返回画布。

添加 Component 不隐式修改连接关系：ConnectionDraft 存在时必须先完成或取消才能进入放置；放到 Wire 上不拆分原 Connection，靠近 Port 不自动吸附或连线。布线期间右键画布背景继续服务当前 Route，不打开元件添加菜单。

## 9. 仿真控制

### 单步

这是初学者的主要操作，也是界面上唯一的推进原语：每按一次推进一个 tick，翻转 Clock 并重新求值到稳定，更新节点和连线、更新输出和波形，并在运行控制组与底部面板反馈已推进的步数。工具栏不提供其它推进动作；「开始 / 暂停 / 继续」只是这一原语的排定方式，与它同处一个运行控制组。

### 连续运行

文案固定为：

```text
开始连续运行 → 暂停仿真 → 继续仿真
```

运行中显示连续仿真状态、步数或时钟信息。连续运行不能隐藏暂停入口。键盘等价路径为 `F5`（开始 / 继续）、`F6`（暂停），与工具栏按钮一一对应，键位登记在 [ADR 0012](../decisions/0012-generic-input-bindings.md) 的键位表。

### 单步执行

属于高级仿真控制，文案使用“执行下一步”，不放在初学者默认工具栏的主要位置。

## 10. 空状态与错误状态

每个状态都要说明发生了什么以及用户可以做什么。

### 用户清空后的空画布

```text
还没有电路

从左侧选择一个元件，或加载一份示例电路开始。

[添加元件]  [加载示例]
```

### 未连接的电路

```text
元件还没有连接

从一个输出端口拖到输入端口，建立第一条连接。
```

### 系统错误

```text
仿真引擎不可用

电路编辑仍然可以继续，但暂时无法运行仿真。

[重新检查引擎]
```

错误不能只通过短暂 Toast 告知，也不能只使用红色。

## 11. 动效与可访问性

- 持续动效只用于 Wire 的信号流向，启用减少动态效果时改为静态信号文字；
- 不使用持续呼吸或高频闪烁作为常规装饰；
- 支持 `prefers-reduced-motion: reduce`；
- 所有可操作元素支持键盘焦点；
- 焦点状态使用清晰的外轮廓；
- 端口的实际命中区域至少为 `24×24px`；
- 错误、成功和信号状态不能只依靠颜色；
- 重要状态使用 `aria-live` 或等效的可访问反馈；
- 画布操作应提供键盘等价路径，至少支持选择、删除、取消和撤销。

## 12. 键盘操作

```text
Ctrl/Cmd + Z              撤销
Ctrl/Cmd + Shift + Z      重做
Ctrl/Cmd + D              复制选中对象
Delete / Backspace        删除选中对象
Esc                       取消连接或退出当前操作
Enter / Space             执行当前聚焦的按钮或开关
F10 / Shift+F10 / 菜单键  在画布焦点处打开元件菜单
```

画布中的方向键按上下文分层，与指针操作等价：

```text
方向键                    移动键盘焦点；布线中移动草稿端点
Shift + 方向键            平移视口
Alt + 方向键              移动聚焦的 Component，一个网格单位
方向键（焦点在 Route 手柄）微调该折点或线段，一个网格单位
Tab / Shift + Tab         在 Component、Wire 和 Port 之间移动焦点
```

Route 手柄（折点与线段）进入方向键导航环但不占用 `Tab` 序：一条折点较多的 Wire 会在 Tab 序里插入大量停靠点，因此 Tab 只在 Component、Wire 和 Port 之间移动，而方向键可以按几何位置导航到手柄。手柄获得焦点后，方向键改为微调该手柄；按 Tab 返回其所属 Wire。

键盘微调与指针拖动使用同一条状态机和同一组控制器：按住的按键累积为一次手势，松开时提交**一条**历史命令，净位移为零时不产生历史记录。视口缩放不进入历史。

```text
Ctrl/Cmd + = 或 +         放大
Ctrl/Cmd + -              缩小
Ctrl/Cmd + 0              适合窗口
```

删除 Component 时，领域 Connection 保留并转为悬空状态，画布继续显示冻结在最后有效端口坐标的悬空 Wire；只有明确删除 Connection 时才移除对应 Wire。上述操作必须可以通过撤销恢复。清空整个画布需要确认。

使用用户能直接理解的动作和结果：


## 14. 工程落地规则

1. 颜色、字体、间距和尺寸通过 Token 管理。
2. 组件样式不得随意新增主题颜色。
3. 页面布局样式和组件状态样式分离。
4. `CircuitNode` 只负责展示和抛出交互事件，不直接负责仿真流程。
5. 创建 Connection 的交互、仿真触发和编辑器状态管理由编辑器控制器或 `EditorSession` 协调；画布展示组件不直接调用仿真引擎，也不持有 Circuit 规则。
6. 公共组件需要覆盖默认、悬停、按下、焦点、禁用、错误和执行中状态。
7. 视觉变更至少通过可重复的手工验收步骤验证。
8. 重要设计变化同步更新本文档和 `docs/decisions/` 中的决策记录。

### 14.1 画布模块接口

画布渲染组件只接收三个聚合输入：`CanvasScene` 描述可渲染对象和信号状态，`ViewportState` 描述平移、缩放和可见范围，`InteractionState` 描述拖动预览、ConnectionDraft、悬停与焦点。`CanvasScene` 由纯投影函数根据 `EditorSnapshot`、`SimulationSnapshot` 和 Component 展示定义生成，不包含固定示例身份。

命中优先级固定为 Port、当前选中 Wire 的折点或线段手柄、CircuitNode、普通 Wire、画布背景。Port 命中区域至少为 `24×24px`，Wire 使用至少 `16px` 的透明命中描边；拖动使用 pointer capture，节点覆盖区域内的 Wire 不得截获节点操作。

拖动和 ConnectionDraft 预览属于临时交互状态，不在 pointer move 期间创建编辑器快照或调用引擎。创建或重接 Connection、一次 Route 编辑、一次 CircuitNode 移动和删除 Waypoint 分别作为单个历史命令提交；取消草稿以及视口平移缩放不进入历史。

重接使用 EditorSession 的补偿事务：旧 Wire 在提交完成前保持可见，删除旧 Connection 后创建新 Connection；失败时重建旧 Connection，全部成功后一次发布快照，补偿失败则进入明确的恢复状态。

引擎不可用时仍允许平移、缩放、移动 CircuitNode 和编辑已有 Route；创建、删除或重接领域 Connection 等结构操作等待引擎恢复。结构提交失败时保留 ConnectionDraft、Waypoint 和当前目标，提供持久错误反馈以及重试、换目标和取消入口，不发布半成品快照。

第一版使用单对象选择；键盘焦点与选择彼此独立，点击空白清除选择，ConnectionDraft 期间冻结普通选择切换。`Esc` 每次只取消最上层状态，优先级依次为模态确认框、提交错误或恢复提示、ConnectionDraft、拖动预览、当前选择。

视口支持滚轮垂直平移、`Shift + 滚轮` 水平平移、`Ctrl/Cmd + 滚轮` 或触控板捏合围绕指针缩放，以及中键拖动、空白处左键拖动或 `Space + 左键拖动` 自由平移。工具栏缩放和 `Ctrl/Cmd + =` / `-` 围绕视口中心，范围为 `25%～400%`；`Ctrl/Cmd + 0` 与工具栏的「适合窗口」都按内容边界计算并保留 `48px` 屏幕留白。

Route 手柄只在所属 Wire 选中时渲染。手柄被取消选中、或因 Route 规范化被合并掉时，浏览器会把键盘焦点静默交给 `body`，画布的键盘事件随之全部失效；画布必须把焦点交还给所属 Wire 并同步键盘焦点状态。

第一版明确不包含小地图、框选、多选、自动避障、Wire crossing bridge、junction、多端 Net、总线、Component 旋转、多人协作光标和完整触屏手势。普通 Wire 交叉不显示 junction 圆点，依靠选中外轮廓确认当前 Wire。

这里的「总线」指的是把一条 Wire 当成多端 Net 的布线概念，与 Phase 4.5 加入的「总线」元件分类不是一回事：多位信号走单条 Connection，拆线与合线由拆线器、合线器两个元件显式表达（[ADR 0017](../decisions/0017-paired-splitter-and-merger.md)），线路上不引入新的画布对象。

### 14.2 画布验证门槛

- Route、坐标转换、吸附和规范化使用纯函数单元测试覆盖；
- ConnectionDraft 使用状态机测试覆盖；
- EditorSession 覆盖创建、重接、取消、补偿失败和撤销；
- Vue 组件覆盖指针和键盘交互；
- 深色与浅色主题、常规与窄窗口执行截图回归；
- 在 1920×1080 视口、500 个 Component 和 1,000 条 Wire 下连续平移或拖动 5 秒，第 95 百分位帧耗时不超过 `20ms`；
- pointer move 每帧最多处理一次，信号更新不得重新计算 Route；超过目标规模时可以关闭光晕、动画和次级网格，但不得移除标签、焦点或操作能力；
- 类型检查和非视觉自动化测试由 `pnpm verify` 统一执行，视觉与性能基准独立运行。
