# 协作约定

1. 先讨论设计，再进行跨模块修改。
2. 对不确定的需求明确标注假设。
3. 重要行为必须有测试或可重复的验证步骤。
4. 代码、测试、文档和架构决策应保持一致。
5. 发现超出角色范围的问题时，记录问题并交给对应角色。
6. 每次交付说明完成内容、验证结果、未完成内容和建议的下一步。
7. 发现需求、设计或实现存在不确定性时，明确记录假设和待确认事项。

## 注释和函数说明

1. 公共函数在声明或导出位置使用中文注释，说明作用、关键参数、返回值和重要错误或状态约束。
2. 内部函数只在存在不明显的设计原因、不变量或副作用时添加注释。
3. 注释解释“为什么”和对调用者重要的行为，不逐行复述代码已经表达的“是什么”。
4. 函数名、类型名和变量名使用英文；面向项目参与者的注释和文档使用中文。
5. 修改函数行为时同步更新注释、测试和相关文档，避免留下与代码不一致的说明。
6. 测试优先使用清晰的测试名称表达行为；只有测试意图不能由名称和结构表达时才补充注释。
